# MouseLens 1.2 Roadmap Design

Updated: 2026-07-13

## Summary

MouseLens 1.2 should move the product from a solid screen-recording utility into a stronger tutorial and walkthrough tool.

The release should focus on three user-visible upgrades:

- better visual presentation
- presenter presence through a camera bubble
- clearer export behavior for common sharing formats

This release should not destabilize the capture architecture that is now working:

- raw video remains cursor-free
- pointer events remain separate
- cursor, click feedback, and camera framing remain reconstructed later
- preview and export must continue to share the same visual composition rules

## Release Goal

Ship a version of MouseLens that makes short demos, tutorials, and product walkthroughs feel more polished without asking users to leave the app for basic finishing work.

In product terms, 1.2 should feel stronger in three moments:

1. choosing a visually good background
2. adding a presenter face bubble when narration matters
3. exporting the result with fewer decisions and less confusion

## Why 1.2 Must Be Decomposed

This version request spans multiple independent subsystems:

- background assets and background rendering rules
- presenter camera capture and composition
- export workflow and export panel interaction
- editor layout polish
- timeline interaction cleanup

These do not belong in a single implementation plan. Each subsystem has different risk, testing needs, and review criteria.

Therefore 1.2 should be handled as one roadmap design and then split into separate implementation plans.

## Product Direction

MouseLens should continue to differentiate itself through the quality of the finished result rather than through raw feature count.

That means 1.2 should prefer:

- curated defaults over deep configuration
- visually consistent output over broad format support
- simple high-frequency workflows over edge-case controls

It should not become a general-purpose nonlinear editor.

## Core Constraints

- Do not reintroduce preview/export drift.
- Do not record the native cursor into the source video.
- Do not tie camera movement directly to cursor movement.
- Keep the editing model understandable for non-expert users.
- New visual options must not compete with the recorded content.
- Every new feature must work for both Screen and Window projects unless explicitly deferred.

## 1.2 Workstreams

### Workstream A: Background System Upgrade

#### Goal

Replace the current mixed background experience with a curated background library that is visually stronger and easier to browse.

#### Scope

- ship eight polished built-in backgrounds
  - four image wallpapers
  - four gradients
- organize backgrounds into clear categories:
  - Wallpaper
  - Gradient
- keep swatch-based selection in the editor
- preserve preview/export parity
- make the asset registration model extensible so new presets can be added later without changing rendering logic

#### Product Rules

- the default set should contain both safe utility presets and stronger showcase presets
- image wallpapers must remain clean enough that the video window remains the main subject
- gradients must differ by composition and lighting behavior, not only hue
- none of the eight presets may reduce content readability

#### Non-Goals

- user-uploaded images
- online background downloads
- animated backgrounds
- background blur/scale/pan editing

#### Acceptance

- all eight presets render consistently in preview and export
- aspect-ratio changes do not break composition
- switching backgrounds feels immediate
- background choice improves the result without making the screen harder to read

### Workstream B: Presenter Camera Bubble

#### Goal

Allow users to add a small talking-head overlay for narrated demos and tutorials.

#### Scope

- optional camera capture for the presenter
- bubble shown as a simple overlay on top of the composition
- editable properties:
  - enabled/disabled
  - position
  - size
  - shape style
  - corner radius or circular mask
  - subtle shadow
- preview and export support

#### Product Rules

- the first version must stay simple
- the bubble should feel like a presentation aid, not like a streaming overlay
- the default should be visually restrained
- placement must avoid fighting with the recording toolbar and future UI overlays

#### Recommended Release Shape

The first shipping version should support:

- four corner positions
- one compact size range
- circular or rounded-rectangle presentation

#### Non-Goals

- background removal
- chroma key
- independent camera timeline editing
- separate camera transitions or animations

#### Acceptance

- recording remains stable while camera bubble is enabled
- bubble position and size are consistent between preview and export
- bubble does not noticeably degrade export reliability

### Workstream C: Export Workflow Refinement

#### Goal

Make export more predictable and simpler to understand.

#### Scope

- keep `MP4` and `GIF` as the two primary export formats
- remove unnecessary format complexity from the user-facing export surface
- make recommended defaults more explicit
- improve size estimation language and accuracy
- make completion and failure states clearer

#### Product Rules

- export should feel decisive, not like a matrix of low-level codec choices
- recommended values should cover most use cases
- settings may remain editable, but only where the choice is meaningful

#### Baseline Defaults

- MP4:
  - `1080p`
  - `30 fps`
  - `High`
- GIF:
  - `720p`
  - `15 fps`

#### Non-Goals

- H.265 rollout
- WebM rollout
- advanced codec tuning
- bitrate sliders
- export queue management

#### Acceptance

- users can understand what to export without reading documentation
- MP4 and GIF both feel first-class
- estimated size messaging is directionally reliable
- export completion states are clear and actionable

### Workstream D: UI System Consolidation

#### Goal

Bring the recording toolbar, recording HUD, editor, and export mode into one consistent visual system.

#### Scope

- unify spacing, type scale, corner radius, and panel framing
- improve long-title handling for capture targets
- clean up proportions between preview, timeline, and inspector
- make export mode feel like a deliberate mode, not an inspector add-on
- reduce accidental visual inconsistencies between screens

#### Product Rules

- the app should feel like one product, not several screens built at different times
- compact utility surfaces should remain compact
- the editor should feel controlled and work-focused, not decorative

#### Non-Goals

- a full app-wide redesign from scratch
- replacing established successful interaction models just for novelty

#### Acceptance

- home toolbar, recording HUD, and editor share the same visual language
- long names do not break layout
- export mode reads clearly at a glance

### Workstream E: Timeline Interaction Polish

#### Goal

Tighten timeline interactions so clip editing and zoom editing feel more precise.

#### Scope

- improve selection clarity across clip and zoom edits
- make split/delete behavior more explicit by selection type
- reduce accidental interaction conflicts between playhead, trim handles, and zoom segments
- maintain immediate visual feedback after edits

#### Product Rules

- timeline behavior must remain simple enough for non-editor users
- selection state must explain which operation will happen before the user triggers it

#### Non-Goals

- multi-track editing
- nested segments
- keyframe authoring UI beyond the existing zoom model

#### Acceptance

- split/delete actions consistently target the selected thing
- deleting zoom segments reverts the affected region immediately
- playhead, trim, and zoom interactions do not fight each other

## Recommended Delivery Order

1. Background System Upgrade
2. Presenter Camera Bubble
3. Export Workflow Refinement
4. UI System Consolidation
5. Timeline Interaction Polish

This order is intentional:

- backgrounds improve perceived quality with relatively low risk
- camera bubble is the biggest new capability and should land after the visual system is stable
- export and UI refinement should absorb the new camera feature cleanly
- timeline polish is valuable but should not block the headline 1.2 value

## Suggested 1.2 Messaging

If the above lands successfully, the external product story for 1.2 should be:

- more polished built-in recording backgrounds
- presenter camera bubble for narrated walkthroughs
- cleaner export workflow with MP4 and GIF
- a more consistent editing experience

## Risks

### Risk: Camera Bubble Destabilizes Capture

Camera capture introduces new runtime complexity, device behavior, and performance risk.

Mitigation:

- keep the first implementation visually simple
- avoid advanced camera effects
- validate preview/export parity before adding polish

### Risk: Background Variety Hurts Readability

Stronger backgrounds can easily become more visually important than the recorded screen.

Mitigation:

- treat all presets as recording compositions, not wallpapers in isolation
- reject any preset that reduces screen legibility

### Risk: Export UI Becomes Over-Designed

Export surfaces often grow into a confusing set of low-level controls.

Mitigation:

- keep only the choices users actually need
- keep the number of export formats intentionally small

### Risk: 1.2 Scope Expands Without End

This roadmap contains several visible features and could easily keep growing.

Mitigation:

- treat each workstream as a separate spec-to-plan-to-implementation cycle
- do not begin the next workstream until the current one has clear acceptance

## Recommended Decomposition For Implementation

This roadmap should not become one implementation plan.

Instead, create separate implementation plans in this order:

1. `Background System Upgrade`
2. `Presenter Camera Bubble`
3. `Export Workflow Refinement`
4. `UI System Consolidation`
5. `Timeline Interaction Polish`

Each plan should include:

- exact files to modify
- preview/export validation strategy
- canonical app verification steps
- regression coverage expectations

## Decision

The next planning action should be to write the first implementation plan for `Background System Upgrade`, unless priorities change and the presenter camera bubble becomes the headline feature for the release.
