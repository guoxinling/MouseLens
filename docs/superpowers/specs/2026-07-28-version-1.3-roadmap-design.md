# MouseLens 1.3 Roadmap Design

Updated: 2026-07-28

## Summary

MouseLens 1.3 should focus on making recorded tutorials easier to understand after capture and easier to present during capture.

The release has three product pillars:

- Speech-to-captions and Notes support
- Cursor style customization
- Simplified Chinese localization

The recommended transcription direction is:

- Apple Speech local/system transcription for the first version
- manual caption editing in the editor
- a clean provider interface reserved for future AI copywriting and cloud transcription

This keeps the first implementation App Store friendly, privacy-conscious, and technically bounded while still creating a meaningful product upgrade.

## Current Baseline

MouseLens already has:

- Screen and Window recording
- raw source video without native cursor
- separate pointer-event recording
- rebuilt cursor, click feedback, zoom, presenter camera, and background composition
- MP4 and GIF export
- preview/export visual parity as a core product constraint

Do not regress these architecture rules:

- Do not record the native cursor into the source video.
- Do not couple cursor motion directly to camera motion.
- Do not introduce separate preview-only, MP4-only, or GIF-only visual composition paths.
- Do not add cloud dependencies to the default recording/export workflow.

## Release Goal

MouseLens 1.3 should help users create clearer narrated demos:

1. Users can generate subtitles from their recording audio.
2. Users can edit subtitle text before export.
3. Users can use lightweight Notes as a teleprompter while recording.
4. Users can choose cursor styles that fit the content and audience.
5. Chinese-speaking users can use the core app flow in Simplified Chinese.

In product terms, 1.3 should make MouseLens feel less like a simple screen recorder and more like a focused demo-production tool.

## Version Scope

### P0: Apple Speech Captions

#### Goal

Generate editable captions from recorded audio using Apple Speech as the first transcription provider.

#### Product Behavior

- After recording, the editor can generate captions from the recorded audio.
- Generated captions appear as timed caption segments.
- Users can edit caption text manually.
- Users can enable or disable captions in preview.
- Export can burn captions into MP4 and GIF output.
- Captions should be optional; projects without captions behave exactly as they do today.

#### Transcription Direction

Use Apple Speech for the first implementation.

Provider behavior:

- Prefer on-device recognition where supported.
- If on-device recognition is unavailable, fail clearly or fall back only if the user explicitly allows system recognition behavior.
- Do not add DeepSeek, OpenAI, Whisper cloud, or any third-party ASR service in 1.3.

Reasoning:

- No API key setup.
- No server cost.
- Lower privacy and App Store review risk.
- Good enough to validate whether users value captions.

#### Data Model

Add a caption model that is independent from video rendering:

```swift
struct CaptionSegment: Codable, Equatable, Identifiable {
    var id: UUID
    var startTime: TimeInterval
    var endTime: TimeInterval
    var text: String
}

struct CaptionTrack: Codable, Equatable {
    var segments: [CaptionSegment]
    var style: CaptionStyle
    var isEnabled: Bool
}

struct CaptionStyle: Codable, Equatable {
    var fontSize: Double
    var position: CaptionPosition
    var textColor: CodableColor
    var backgroundColor: CodableColor
    var backgroundOpacity: Double
}

enum CaptionPosition: String, Codable, Equatable {
    case bottom
    case center
    case top
}
```

The exact Swift names can follow existing project naming conventions during implementation, but the model should preserve these responsibilities.

#### Provider Boundary

Add a transcription provider boundary:

```swift
protocol TranscriptionProvider {
    func transcribe(audioURL: URL, locale: Locale) async throws -> CaptionTrack
}
```

Initial provider:

- `AppleSpeechTranscriptionProvider`

Reserved future providers:

- `CloudTranscriptionProvider`
- `WhisperTranscriptionProvider`
- `AITranscriptRefinementProvider`

These future providers should not appear in the 1.3 UI.

#### Editor UI

Add a `Captions` section or mode in the editor.

Minimum controls:

- Generate Captions
- Caption on/off
- Language selector, defaulting to system language
- Caption list with editable text
- Caption style controls:
  - font size
  - position
  - background opacity

The first version should not attempt a full subtitle timeline editor. A list editor plus preview sync is enough.

#### Export

Captions must use the same composition path as preview.

Rules:

- Preview and export use the same caption layout function.
- MP4 and GIF both support burned-in captions.
- Caption timing respects trim range.
- Caption position is relative to the visible composition canvas, not the raw source video.

#### Privacy and Permissions

Expected permission/copy implications:

- Add or verify the Speech Recognition usage description if Apple Speech requires it.
- Explain that speech recognition is used to create captions from the user's recordings.
- Do not imply cloud transcription unless cloud transcription exists.

### P1: Notes / Teleprompter

#### Goal

Give users a lightweight way to prepare and follow talking points while recording.

#### Product Behavior

- User can write `Notes` before recording.
- Notes can be shown during recording as a floating teleprompter panel.
- Notes are not captured into the source recording.
- Notes are stored with the project for later reference.
- The UI should use `Notes`, not `Prompt`, because `Prompt` can be confused with AI model instructions.

#### First Version Scope

Keep the first version simple:

- plain text Notes
- show/hide during recording
- draggable floating Notes panel
- font size adjustment

Do not include in 1.3:

- AI-generated scripts
- automatic scrolling
- rich text formatting
- script timing
- multi-scene Notes cards

#### Future AI Expansion

Reserve a future AI text workflow:

- generate a script from a topic
- summarize transcript
- generate title and description
- rewrite captions into cleaner narration

This should be behind a future provider boundary and should not block 1.3.

### P1: Cursor Style Customization

#### Goal

Let users choose a cursor style that fits the recording context while preserving the existing rebuilt-cursor architecture.

#### Product Behavior

- Users can choose cursor style in the editor.
- Cursor style applies immediately in preview.
- Cursor style is preserved in MP4 and GIF export.
- Existing projects keep the current white cursor as default.

#### Cursor Asset Source

The user will provide candidate cursor styles before final implementation.

Implementation should not invent the final cursor visuals. The first development milestone should create the data model, preview/export style plumbing, and a placeholder style catalog. Final visual assets should be swapped in after the user provides the selected cursor designs.

Cursor asset requirements to request from the user:

- PNG or SVG source for each cursor style.
- Transparent background.
- At least 512 px on the longest side for raster PNG assets.
- A clearly marked cursor hotspot/tip coordinate for each arrow style.
- A visible click center for dot-style cursors.
- Style names or intended use cases if available.

#### Initial Cursor Styles

Ship a small built-in style set after the user provides the final visual candidates:

1. White Arrow
   - current default
   - best general-purpose style

2. Black Arrow
   - useful on light screens

3. High Contrast Arrow
   - white fill, dark outline, stronger shadow
   - best for tutorials and accessibility

4. Soft Pointer
   - slightly rounded, polished teaching style

5. Focus Dot
   - circular cursor alternative for product demos
   - no arrow direction ambiguity

Do not add too many styles in the first release. A small useful set is better than a large inconsistent library.

#### Cursor Controls

Minimum controls:

- Style
- Size
- Shadow strength
- Click ripple color
- Click ripple intensity

Keep advanced controls out of 1.3:

- custom cursor image upload
- animated cursors
- per-segment cursor styles
- cursor trail effects

#### Architecture Rule

Cursor style must be applied at render time to reconstructed pointer events.

Do not:

- record the native cursor
- bake cursor style into source video
- maintain separate preview/export cursor drawing logic

### P1: Simplified Chinese Localization

#### Goal

Add a Chinese version for the core MouseLens app flow.

#### Product Behavior

- The app follows the user's macOS language preference.
- If the system language is Simplified Chinese, core UI appears in Chinese.
- If the system language is not supported, the app falls back to English.
- App Store metadata can be prepared separately for Chinese-speaking storefronts if needed.

#### First Version Scope

Localize the core user-facing surfaces:

- Home recording toolbar
- Recording countdown and recording HUD
- Editor header
- Video/background controls
- Motion and Zoom controls
- Presenter Camera controls
- Captions controls
- Notes controls
- Cursor controls
- Export panel
- Permission prompts and MouseLens-owned error states

Do not include in 1.3:

- Chinese rewrite of all internal documentation
- localized marketing website redesign
- multi-language App Store screenshot set
- Traditional Chinese unless explicitly requested later

#### Copy Rule

Use clear product language, not direct machine translation.

Examples:

- `Captions` -> `字幕`
- `Generate Captions` -> `生成字幕`
- `Notes` -> `讲解提纲`
- `Cursor Style` -> `鼠标样式`
- `Smart Zoom` -> `智能放大`
- `Presenter Camera` -> `讲解人头像`
- `Export GIF` -> `导出 GIF`

## Recommended 1.3 Milestones

### Milestone 1: Caption Model and Apple Speech Prototype

Deliverable:

- Project can store caption segments.
- Editor can generate captions from a recorded audio file.
- Captions can be shown in preview as plain text.

Acceptance:

- A short recording produces timed caption segments.
- Caption data persists after closing and reopening the project.
- Projects without captions remain unchanged.

### Milestone 2: Caption Editing and Styling

Deliverable:

- Users can edit generated caption text.
- Users can enable/disable captions.
- Users can adjust basic caption style.

Acceptance:

- Edited text appears immediately in preview.
- Caption position and style are stable across preview resize.
- Caption timing respects clip trim.

### Milestone 3: Caption Export

Deliverable:

- MP4 and GIF export include burned-in captions when enabled.

Acceptance:

- Exported captions match preview at the same timestamp.
- Trimmed exports preserve correct caption timing.
- Export without captions is visually unchanged.

### Milestone 4: Notes / Teleprompter

Deliverable:

- Recording toolbar supports Notes.
- Notes panel can be shown during recording without being captured.

Acceptance:

- User can write Notes before recording.
- Notes appear during recording.
- Notes do not appear in source video, editor preview, or export unless explicitly implemented later as an overlay.

### Milestone 5: Cursor Style Library

Deliverable:

- Editor supports selecting cursor style and core cursor parameters.

Acceptance:

- Cursor style updates immediately in preview.
- MP4 and GIF exports match preview.
- Existing cursor/click/zoom coordinate behavior does not regress.

### Milestone 6: Simplified Chinese Localization

Deliverable:

- Core app UI supports English and Simplified Chinese.

Acceptance:

- The app displays Chinese strings when macOS language is Simplified Chinese.
- The app falls back to English for unsupported languages.
- New 1.3 UI surfaces use the same localization system as existing UI.
- No visible placeholder localization keys appear in the app.

## Testing Strategy

### Unit Tests

Caption model:

- encode/decode caption tracks
- trim-aware caption timing
- caption lookup by timestamp

Caption layout:

- bottom/top/center placement
- safe-area behavior
- style opacity and font-size mapping

Transcription provider:

- provider result maps to `CaptionSegment`
- provider failure produces clear UI state
- unsupported locale or unavailable on-device recognition is handled explicitly

Cursor style:

- default style migration
- style encode/decode
- preview/export cursor geometry uses the same style config

Localization:

- required localization keys exist in English and Simplified Chinese
- unsupported locale falls back to English
- new 1.3 UI strings are not hard-coded in Swift views

### App Verification

Manual app flows:

- record with microphone enabled
- generate captions
- edit caption text
- export MP4 with captions
- export GIF with captions
- record with Notes visible
- confirm Notes are not captured
- switch cursor styles and export
- switch macOS/app language environment and verify Chinese UI copy

Regression flows:

- Screen recording with cursor, zoom, presenter camera, and captions
- Window recording with cursor, zoom, presenter camera, and captions
- GIF export with cursor style and captions
- MP4 export with cursor style and captions

## App Store Review Considerations

This version may introduce Speech Recognition permission.

Review-safe positioning:

- Speech recognition is used to create captions from the user's own recording.
- Captions are user-editable.
- No accessibility APIs are required.
- No cloud AI service is used by default.
- Privacy copy should explicitly describe audio transcription behavior.
- Chinese localization should not imply cloud AI transcription or online processing unless that feature exists.

If future cloud transcription or AI writing is added, privacy policy and App Store metadata must be updated before submission.

## Non-Goals for 1.3

Do not include:

- cloud ASR
- DeepSeek/OpenAI text generation
- Whisper model bundling
- virtual avatars
- background removal for presenter camera
- custom cursor image upload
- agent-generated cursor visual assets without user approval
- multi-track subtitle editing
- SRT/VTT import/export, unless caption architecture is complete early and there is low risk
- Traditional Chinese localization

## Open Decisions

Before implementation, decide:

1. Should Apple Speech require strictly on-device recognition, or allow system-managed recognition after explicit user consent?
2. Which caption languages should be exposed first: system language only, Chinese/English only, or all Apple Speech supported locales?
3. Should captions be enabled by default after generation, or generated but off until the user toggles them on?
4. Should the teleprompter ship in the same release as captions, or follow after caption export is stable?
5. Should cursor style controls live under a new `Cursor` inspector section or inside the existing Motion/Video inspector?
6. Which final cursor assets should ship in 1.3?
7. Should Chinese App Store metadata and screenshots ship with 1.3, or only the in-app Chinese UI?

## Recommended Scope Cut If Schedule Is Tight

If 1.3 needs to ship quickly, cut scope in this order:

1. Cut Notes / teleprompter.
2. Cut Focus Dot cursor.
3. Cut Chinese App Store metadata while keeping in-app Chinese UI.
4. Cut GIF caption export if MP4 caption export is stable but GIF timing is risky.
5. Cut caption style customization beyond size and bottom position.

Do not cut:

- manual caption editing
- preview/export caption parity
- existing cursor/zoom correctness tests
